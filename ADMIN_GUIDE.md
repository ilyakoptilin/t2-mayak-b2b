# Руководство администратора (B2B-ассистент «Маяк»)

Документ предназначен для системных администраторов и инженеров (MLOps), поддерживающих работоспособность системы и актуальность базы знаний.

## 1. Архитектура RAG-системы
- **Векторная БД:** ChromaDB (хранится локально в `/chroma_db`).
- **Модель эмбеддингов:** `intfloat/multilingual-e5-small` (размер ~400 МБ, загружается автоматически при первом запуске).
- **LLM Engine:** Ollama / Qwen 3 (интеграция через REST API, порт 11434).

## 2. Обновление Базы Знаний
Документы не загружаются в систему напрямую. При изменении корпоративных регламентов необходимо пересобрать векторное хранилище.

**Шаги по обновлению:**
1. Поместите свежий файл с распарсенными текстами `b2b_knowledge_base_raw.json` в корень проекта.
2. Убедитесь, что сервер FastAPI остановлен.
3. Запустите скрипт сборки базы данных:
   ```bash
   python build_vector_db.py
   ```
4. Скрипт автоматически удалит старую директорию `chroma_db/`, переведет новые тексты в эмбеддинги (добавив префикс `passage: `) и сохранит их.
5. После появления сообщения об успешной загрузке батчей, базу можно использовать.

## 3. Тестирование и мониторинг
Перед деплоем новых версий обязательно прогоняйте пакет автотестов.

**Запуск Unit-тестов и API-тестов:**
Проверка бизнес-логики, обработки ошибок 422/500 и валидации (без обращения к реальной LLM):
```bash
pytest test_backend.py -v --cov=main
```

**Запуск UI-тестов (End-to-End):**
Проверка доступности Swagger UI и рендера интерфейса с помощью Playwright:
```bash
pytest test_ui.py -v
```

## 4. Возможные проблемы
- **Ошибка "Connection refused" от LLM:** Убедитесь, что процесс `ollama serve` запущен в фоновом режиме.
- **Ошибки памяти при сборке БД:** Если JSON-файл превышает 500 МБ, уменьшите параметр `BATCH_SIZE` в файле `build_vector_db.py` (по умолчанию 5000).
